# Learnings — surface

- When a control is renamed for what it really does, align its styling too (no destructive style on a reversible act) — because colour reaches the reader before the label.
- When a notice claims an ordering, completeness or remedy, assert that claim (position, the other branch), not the sentence's presence — because counts and membership pass under every wrong wording.
- When you bound a result by arithmetic, name every term that scales with the same N — because the term left out is the one that dominates.
- When an artifact rules on a detail view, check what the listing above it does with the same rule — because a rule stated at one level does not enforce itself one level up.
- Before advertising an action, build a real call using only shipped surfaces — because a test reaching past the surface for an argument hides that no caller can obtain it.
- When a result gains a collection, write down what bounds it before deciding it needs no cap — because a gate is not a cap, and the false bound announces itself once written.
- Before a UI or notice says 'do X to fix this', grep for the endpoint and control that let a user do X — because the wording ships as a promise.
